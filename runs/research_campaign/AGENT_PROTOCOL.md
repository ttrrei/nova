# Dedicated direction agent protocol

You own one assigned family for all three stages. Work only in runs/research_campaign/FAMILY/. Read AGENTS.md, docs/DESIGN.md, strategies/directions/FAMILY.yaml, this protocol and relevant earlier evidence. The coordinator maintains shared code and catalogs. Do not edit source/features/scripts/shared docs, other families, or background/legacy. Use the family's already cloned catalog; do not create or alter stores elsewhere.

For the assigned phase conduct exactly20 successful, audited, semantically distinct hourly YAML experiments. Phase1 explores; phase2 incorporates the coordinator's global stage1 review; phase3 incorporates stage2 review. Stop after the assigned20 and send results; never cross a stage barrier without the coordinator's follow-up. Across all60, display ID/hypothesis changes or boolean reordering do not constitute a new hypothesis.

Per round create an immutable candidate YAML under your strategies directory, with clear direction-specific hypothesis, then run:
`.venv/bin/python scripts/research_round.py --family FAMILY --phase PHASE --round N --strategy PATH --hypothesis 'expected mechanism' --change 'specific change from parent' --lesson 'what this test will distinguish' --parent PARENT_RUN_ID`
The helper produces exact per-instrument results, independent ledger audit and immutable phase_N/round_XX.json. READY.json must exist and match the frozen engine. Each phase must have20 completed records; failures/attempt logs do not count. Retain losing hypotheses and transparently retry infrastructure errors.

Research is adaptive: inspect each result before deciding the next candidate. Prefer single changes, branch from observations, compare nearby settings, include controls and failed ideas, then combine changes when supported. Do not pre-generate a blind grid of20 and call it learning. A small local driver that picks the next documented hypothesis using prior observations is acceptable; strategy content itself must remain YAML with reviewed compiler operators and features. No Python callbacks/SQL/eval in YAML. Do not implement an unbounded generator.

All rounds use all21 instruments, full available hourly history, identical rule thresholds/feature parameters across instruments, the2% entry-fill adverse-price mandatory stop and current next-observed-open fills/one-trade rules. Do not restrict assets or alter data windows. Existing feature vocabulary only. Baseline cost assumptions: spread fallback2bps, adverse slippage0.2bps per side, commission/financing0. Never lower costs. Higher costs may be a clearly labeled diagnostic in later stages and must not replace the main-assumption comparison. Preserve direction identity. Relative strength is time-series normalized strength, not cross-asset ranking; structure uses causal rolling boundaries; volume is quote activity; session is a fixed UTC rule, not exchange/DST sessions.

After every result append a short actual observation and lesson to phase_N/learning.md, explaining why the next change follows. The CLI --lesson is the pre-run expected learning, not your post-run interpretation. Preserve all21 individual results in the round JSON. Selection is descriptive: maximize instruments passing the established monthly-opening/positive-score screen, break ties with median score of passing instruments then median score across21. Never sum instrument returns into a portfolio. No new extra promotion gate; yearly concentration, monthly zeros, cost sensitivity and negative controls inform interpretation rather than silently changing the user's acceptance criterion. Selected historical maxima remain adaptive historical research, not independent validation.

At phase end write phase_N/review.md:20round table (change, passcount, key lesson), winner round/run/YAML and all passing names, material score/frequency tradeoffs, yearly fragility, failures, recommendations for nextstage. Send root concise results and record locations. Remain available for later phase follow-up under the same agent identity.
