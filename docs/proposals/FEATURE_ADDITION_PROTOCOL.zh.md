# 特征新增协议（待人工审核）

状态：**提案** — 供人工审核，尚未批准。
中文对照：本文件；英文版为 `FEATURE_ADDITION_PROTOCOL.md`（两版不一致时以英文版为准）。

## 为什么

Nova 的核心是冻结的，因为对因果性、引擎、执行或成本规则、指标或依赖的
任何改动都会使所有历史结果失效。**新增**特征是特征变更中唯一可以做成
“只增不改”的类别——它不改动任何现有列——因此在上文证明要求全部满足的
前提下，不会使历史失效。

## 允许（只增不改）

当且仅当以下全部条件成立时，可以新增特征：

1. 具有唯一的新名称，占用新列；不触碰任何现有特征列。
2. 已登记到特征目录（catalog）。
3. 按 `AGENTS.md` 的要求递增 `FEATURE_VERSION`。
4. 因果性测试覆盖新列（逐 bar、仅过去语义）。
5. 在变更被接受**之前**，下文全部证明要求均已满足。

## 未经明确人工决定不允许

- **更新**：改动任何现有特征的公式、参数、预热、dtype、NaN 规则或行过滤。
- **重命名**：重命名任何现有特征。
- **删除**：移除任何现有特征或其列。
- 对引擎、执行、成本或指标的任何改动。
- 任何依赖变更（包括 `pyproject.toml` 或 `requirements.lock`）。

## 接受新增前必须提供的证明

1. 变更前后，**所有**现有特征列的指纹（按品种、按周期）完全一致。
2. 变更前后行时间戳完全一致。
3. `requirements.lock` 未变。
4. 重放历史运行可复现完全相同的交易列表。
5. 引擎不按位置选取列，且在特征路径任何位置不使用 `SELECT *`。

指纹与重放工具将在**后续的特征新增任务**中构建，不在本仓库整理计划内。

## 如果必须更新现有特征

仅使清单（manifest）中列出该特征为依赖的运行失效。这些运行必须在
**人工决定之前**从清单中列出，以便人工看到哪些历史结果受到风险影响。
