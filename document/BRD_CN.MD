## 1. 项目概述

### 1.1 项目背景

随着量化交易市场竞争日趋激烈，Alpha 策略的发现效率与质量成为机构投资者的核心竞争力。然而，传统策略开发存在以下痛点：

- **人工依赖高**：策略研发依赖经验丰富的交易员，效率低且难以规模化
- **过拟合风险大**：小样本回测导致策略在实盘中表现不佳
- **算力成本高**：海量策略候选空间的穷举测试带来巨大计算开销
- **策略同质化**：缺乏系统化的去重机制，导致大量冗余策略浪费计算资源

**Nova** 应运而生，旨在构建一个**极轻量、高复用、低算力成本**的 Alpha 策略自动发现与寻优引擎。

### 1.2 项目定位

| 维度 | 说明 |
|------|------|
| **核心定位** | Alpha 策略探索与寻优引擎 |
| **核心价值** | 极轻量、高复用、低算力成本 |
| **交付形式** | 托管于 GitHub 的轻量 Python 代码库 |
| **设计原则** | 能跑即用，拒绝过度工程化 |

### 1.3 工程边界

> **重要说明**：本项目严格聚焦于策略寻优与 Alpha 算法验证，以下模块作为独立的后续工程，不在本项目范围内：

- 实盘订单执行系统
- 流式实时计算引擎
- 运维监控与告警系统
- 资金管理与仓位控制系统

## 2. 业务目标与核心需求

### 2.1 核心业务目标

| 目标编号 | 业务目标 | 量化指标 |
|----------|----------|----------|
| **BG-01** | 建立自动化策略发现管线 | 从构想端到评估端全流程自动化，无需人工干预 |
| **BG-02** | 实现 AI 驱动的策略生成 | Gemini + Gemma 多模型协作，生成多样化 Alpha 策略 |
| **BG-03** | 构建严格的防过拟合体系 | 时间均匀性 + 胜率稳定性双重硬约束 |
| **BG-04** | 优化算力成本 | 四级递进去重引擎，拦截冗余策略 |
| **BG-05** | 支持策略自我进化 | Schema 演进管道，持续吸收未支持的策略逻辑 |

### 4.1 多时间框架状态转换策略

```
┌─────────────────────────────────────────────────────────────┐
│                     状态转换入场模型                          │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│    1h K线 ─── 趋势方向判定 ───┐                              │
│                               ├──► 状态转换入场信号           │
│    5m K线 ─── 入场点捕捉 ─────┘                              │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 入场逻辑说明

| 时间框架 | 职责 | 关键约束 |
|----------|------|----------|
| **1 小时周期** | 确定趋势方向偏好 | — |

## 5. 评估指标体系

### 5.1 基础绩效指标

| 指标 | 计算方式 | 合格阈值 |
|------|----------|----------|
| **夏普比率 (Sharpe Ratio)** | 超额收益均值 / 收益标准差 | > 1.0 |
| **卡玛比率 (Calmar Ratio)** | 年化收益 / 最大回撤 | > 1.5 |
| **盈亏比 (Profit Factor)** | 总盈利 / 总亏损 | > 1.2 |
| **最大回撤 (Max Drawdown)** | 历史权益高点至低点的最大跌幅 | < 20% |

### 5.2 防过拟合硬约束

| 约束类型 | 具体要求 | 判定标准 |
|----------|----------|----------|
| **时间均匀性** | 每周/每月交易笔数稳定分布 | 无显著聚集或稀疏期 |
| **胜率稳定性** | 周/月度胜率标准差 | σ_win_rate < 0.15 |

### 5.3 高阶评估指标

| 指标 | 定义 | 评估目的 |
|------|------|----------|
| **持仓姿态比** | T_profit / T_loss（正/负收益持仓时间比） | 评估入场精准度 |
| **权益厚度 (Area Ratio)** | ∫PnL_+(t)dt / ∫|PnL_-(t)|dt | 评估盈利"厚度"与回撤"深度" |
| **First-to-Hit 率** | 率先触及指定收益/亏损比例的分布概率 | 评估目标达成效率 |

## 8. 设计哲学

| 原则 | 描述 |
|------|------|
| **能跑即用** | 拒绝过度工程化，轻量 Python 代码库，托管于 GitHub |
| **纯 Alpha 优先** | 剥离仓位管理与执行层，专注评估策略本身的信号质量 |
| **AI 即工具链** | AI 模型是策略工厂的工人，不是黑箱决策者 |
| **防过拟合为第一原则** | 时间均匀性、胜率稳定性、信号相关性去重，层层过滤伪策略 |
| **可演进的表达力** | 未支持的想法不丢弃，沉淀 → 审查 → 升维，系统自我进化 |
