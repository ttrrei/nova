## 1. 系统概述

### 1.1 系统定位

Nova 是一个面向量化交易的 Alpha 策略自动发现与寻优系统，采用多时间框架状态转换策略为核心交易范式，通过 AI 驱动的策略生成管线与向量化回测引擎，实现策略从构想、编译、去重到评估的全自动闭环。

### 1.2 系统边界

| 纳入范围 | 排除范围 |
|----------|----------|
| 策略寻优与 Alpha 算法验证 | 实盘订单执行 |
| AI 策略生成管线 | 流式实时计算 |
| 向量化回测引擎 | 运维监控与告警 |
| 四级递进去重引擎 | 资金管理与仓位控制 |

## 3. 数据架构

### 3.1 Medallion Architecture

采用 Medallion Architecture 结合 DuckDB 本地向量化查询，构建 Bronze → Silver → Gold 三层数据架构：

```
┌────────────────────────────────────────────────────────────────────┐
│                        Medallion 数据架构                           │
├────────────────────────────────────────────────────────────────────┤
│                                                                    │
│   OCI Object Storage                                                   │
│   (外部 VM 采集 OANDA API 数据)                                         │
│        ▼                                                           │
│   ┌─────────┐     ┌─────────┐     ┌─────────┐                     │
│   │ Bronze  │────►│ Silver  │────►│  Gold   │                     │
│   │ 原始层   │     │ 清洗层   │     │ 特征层   │                     │
│   └─────────┘     └─────────┘     └─────────┘                     │
│        │               │               │                          │
│        ▼               ▼               ▼                          │
│   Parquet           Parquet         Parquet                        │
│   (OCI Storage)    (本地)          (本地)                          │
│                                                                    │
└────────────────────────────────────────────────────────────────────┘
```

### 3.2 Bronze Layer（原始层）

| 项目 | 规格 |
|------|------|
| **数据来源** | OCI Object Storage（上游由外部 VM 通过 OANDA API 采集） |
| **数据内容** | 1 分钟 OHLCV 原始数据 |
| **存储格式** | Parquet |
| **存储位置** | OCI Object Storage |
| **分区策略** | 按年 / 月 / 标的分区 |
| **保留策略** | 完整保留原始数据，不可变性 |

### 3.3 Silver Layer（清洗层）

| 项目 | 规格 |
|------|------|
| **数据内容** | 清洗对齐后的基表 |
| **重采样** | 1min → 5min / 1h |
| **Session 隔离** | 标记休市/隔夜 Session |
| **防畸变处理** | 跨周末/跨休市窗口 Rolling 计算隔离 |
| **存储格式** | Parquet (本地) |

### 3.4 Gold Layer（宽表特征库）

| 项目 | 规格 |
|------|------|
| **特征类型** | feat_trend.parquet, feat_volatility.parquet, feat_momentum.parquet |
| **参数稀疏化** | [12, 24, 48, 72] 等代表性参数 |
| **查询方式** | DuckDB VIEW 零拷贝拼接 |
| **存储格式** | Parquet (本地) |

### 3.5 数据查询机制

```python
# DuckDB VIEW 实现基表与宽表无缝拼接
CREATE VIEW strategy_signals AS
SELECT
    s.timestamp,
    s.close,
    t.ema_12, t.ema_24, t.ema_48, t.ema_72,
    v.atr_12, v.atr_24, v.atr_48, v.atr_72,
    m.rsi_12, m.rsi_24, m.rsi_48, m.rsi_72
FROM silver_5m s
JOIN gold_trend t ON s.timestamp = t.timestamp
JOIN gold_volatility v ON s.timestamp = v.timestamp
JOIN gold_momentum m ON s.timestamp = m.timestamp;
```

## 4. 多时间框架对齐机制

### 4.1 未来函数消除

| 约束 | 实现方式 |
|------|----------|
| **5min 信号计算** | 调用 1h 特征时严格锁定为上一根已完全收盘的 1h K 线 |
| **时间戳对齐** | 基于 UTC 时间戳精确匹配 |
| **边界处理** | Session 边界不跨期引用特征 |

### 4.2 时间框架职责划分

| 时间框架 | 职责 | 数据来源 |
|----------|------|----------|
| **1 小时** | 趋势方向判定 | Gold Layer 1h 基表 |
| **5 分钟** | 入场点捕捉 | Gold Layer 5m 基表 + 1h 特征 |

## 6. 回测引擎设计

### 6.1 核心机制

| 机制 | 实现方式 | 目的 |
|------|----------|------|
| **R-Multiple 归一化** | 按初始止损距离标准化为 1R | 剥离仓位管理，评估纯 Alpha |
| **悲观碰撞判定** | 同根 5min K 线 TP/SL 同时触达时优先止损 | 保守评估，避免过度乐观 |
| **单持仓状态机** | 同标的持仓未平仓前忽略后续信号 | 防止叠加开仓 |
| **零防抖设计** | 不设时间冷却 | 将震荡磨损作为 Alpha 覆盖能力硬指标 |

### 7.2 去重层级详情

| 层级 | 机制 | 拦截时机 | 计算复杂度 |
|------|------|----------|------------|
| **Level 1** | AST 重排 + 参数网格化 | YAML 生成后 | O(n) |

## 11. 安全性与容错

### 11.1 沙盒防御机制

| 机制 | 实现方式 |
|------|----------|
| **AST 静态审查** | 拦截包含向前看语法的 Python 代码 |
| **Tail Check** | 追加新 K 线验证历史特征值不变 |
| **未来函数检测** | 5m 信号计算严格引用已收盘 1h K 线 |

### 11.2 异常处理

| 场景 | 处理方式 |
|------|----------|
| **API 调用失败** | 指数退避重试，失败告警 |
| **回测超时** | 单标的超时隔离，继续其他标的 |
| **AI 生成失败** | 降级至模板策略，记录 Backlog |
